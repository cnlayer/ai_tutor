# 家长监护（v1.1–v1.3）

家长定义孩子可以聊什么、以及每类话题用哪种方式回答。v1.3 起有**两份白名单**：**引导式白名单**（作业辅导类，先问思路、给提示不给答案）和**直接讲解白名单**（知识类，按年级水平直接给介绍）；两份都不命中的话题软性拒绝。家长可以增删两份白名单、补充自定义规则、维护禁区关键词。

## 两层防护

1. **提示词白名单（主防线）**：插件把家长定义的**两份白名单 + 路由规则**作为高优先级系统提示注入每一次模型调用。模型对每条孩子消息先判断命中哪份白名单，再选回复模式（见下文[两种回复模式与话题路由](#两种回复模式与话题路由v13)）；两份都不命中的请求温和拒绝并引导回作业；孩子要求"解除规则"或"扮演其他角色绕过"时保持立场。
2. **消息级硬拦截（兜底）**：孩子消息命中家长设置的**禁区关键词**时，插件会在进入模型的那条消息末尾追加一条监护指令（会话记录和孩子界面上都看不到这条指令），模型据此拒绝执行该请求。

> 定位说明：关键词匹配是粗粒度兜底，主防线是提示词白名单。更强的语义级分类（用小模型逐条判定）在路线图上，未进 v1.1。

## 家长怎么配置

### 当前入口：编辑 profile patch 文件（v1.1 唯一入口）

编辑 `~/.dsh/profiles/ai-tutor/cordis.patch.yml`（Windows 为 `C:\Users\<你>\.dsh\profiles\ai-tutor\cordis.patch.yml`），在文件**末尾**追加对 guard 行的 config 覆盖（写完整对象）：

```yaml
- id: ai-tutor-guard
  config:
    enabled: true
    guidedTopics:                       # 命中 → 引导式辅导（先问思路、给提示不给答案）
      - 写作业、解题、错题订正等作业辅导内容
      - 英语单词与课文背诵
      - 数学思维训练题
    directTopics:                       # 命中 → 直接讲解（按年级水平直接给介绍，不反问）
      - 科学、学术与知识性问题（天文、物理、化学、生物、地理、历史、文化常识等）
      - 语文与英语的语言知识（词义、语法、成语、例句、发音）
    extraPolicy: |
      周末下午 4 点前只允许数学和语文作业辅导。
    blockedKeywords:
      - 陪我聊天
      - 打游戏
```

保存即热生效（profile 以 `patchReload: live` 运行）；不确定时重启服务（`sudo systemctl restart ai-tutor`）。改动写在 patch 层，**升级不丢失**。没写的字段取默认值（例如只写 `guidedTopics` 时，`directTopics` 仍是默认的科学知识类）。

字段说明：

| 字段 | 说明 | 默认值 |
| --- | --- | --- |
| `enabled` | 监护总开关 | 开 |
| `guidedTopics` | **引导式白名单**：命中后走引导式辅导（列表，每行一条） | 写作业、功课讲解、错题订正等作业辅导内容 |
| `directTopics` | **直接讲解白名单**：命中后按年级水平直接讲解，不反问、不引导 | 科学/学术与知识性问题；语文与英语的语言知识 |
| `allowedTopics` | 已废弃（v1.2 的单一白名单）：非空时**并入 `guidedTopics`**（去重），旧配置升级后行为不变 | 空 |
| `extraPolicy` | 自定义补充规则，原文注入系统提示 | 空 |
| `blockedKeywords` | 禁区关键词（子串匹配，大小写不敏感） | 陪我聊天、玩游戏、打游戏、看小说、写小说 |
| `purgeArchivedFiles` | 清空历史时物理删除会话日志文件（见下节） | 开 |
| `sessionsRoot` | 会话存储根目录；留空自动取 `$DSH_HOME/sessions` | 空（自动） |

## 两种回复模式与话题路由（v1.3）

同一个 ai-tutor 有两种回复模式，用哪一种由**这条消息命中哪份白名单**决定：

| 命中 | 回复模式 | 表现 |
| --- | --- | --- |
| `directTopics` | **模式 A 直接讲解** | 第一句就给结论，再按年级补 2–4 个要点 + 生活化例子，一次讲完（约 150–300 字），结尾最多一个轻问题；不反问、不要求孩子先猜 |
| `guidedTopics` | **模式 B 引导式辅导** | 先问"你是怎么想的、卡在哪一步"，拆台阶给提示不报答案；连续 3 轮无进展才问"要不要我完整讲一遍" |
| 都不命中 | **软性拒绝** | 一句话说明"这个不在我们约定的范围里"，随即给一个回到作业的具体引导；不批评、不说教、不解释监护规则细节 |

判定顺序与歧义处理（写进注入的系统提示，模型每条消息执行一次）：

1. 先看是否命中 `directTopics`，再看 `guidedTopics`。
2. **两份都命中**时按问法定：孩子给出具体的题目、要求解出/算出/批改/订正 → 模式 B；只是问"是什么/为什么/怎么回事"这类知识 → 模式 A。例如"黑洞"这一知识点走模式 A，"这道关于黑洞的阅读理解题帮我看看"走模式 B。
3. 拿不准时：明显是知识性提问就按模式 A 先给一段简短介绍；否则问一句"这和今天的作业有关吗？"，确认有关再按模式 B。
4. 命中任一白名单的请求**必须正常回应**，不得拒绝或强行拉回作业——这是"菜谱、背诵、聊天"这类非作业白名单条目不被误伤的前提。

两种模式的**讲法**写在 preset 人格里（`dsh-ai-tutor/cordis.patch.yml` 的 `## 回复模式`），**路由与白名单**在 guard 里（`dsh-ai-tutor-guard/index.js` 的 `buildPolicy`）。年级处理：孩子说过年级就按那个年级讲；没说过时按小学高年级到初中水平先讲，并在结尾问一句年级——不会为了问年级而不回答。

改完白名单或文案，可以先离线看一遍模型实际读到的指令，不用启动服务：

```powershell
node scripts/guard-policy.mjs                 # 默认配置
node scripts/guard-policy.mjs my-guard.json   # JSON 里放 patch 中 ai-tutor-guard 的 config
```

### 从 v1.2 的 `allowedTopics` 迁移

v1.2 只有一份 `allowedTopics`，所有允许的话题都是引导式。升级到 v1.3 **不改配置也能跑**：旧字段的内容会自动并入引导式白名单，同时 `directTopics` 的默认值（科学、学术知识类）开始生效——知识类问题会直接讲。

想精确控制，就把旧字段拆成两份，例如原来配了「查询菜谱、厨艺」「轻度聊天」这类生活话题，它们属于引导式还是直接讲解，按你想要的讲法放：

```yaml
    guidedTopics:
      - 写作业、解题、错题订正等作业辅导内容
      - 英语单词与课文背诵
      - 数学思维训练题
      - 轻度聊天
    directTopics:
      - 科学、学术与知识性问题（天文、物理、化学、生物、地理、历史、文化常识等）
      - 查询菜谱、厨艺等相关内容
```

拆开后删掉 `allowedTopics` 即可。不想让孩子直接讲知识，就把 `directTopics` 设成空列表 `[]`（回到 v1.2 的全引导行为）。

## 清理会话历史（v1.2）

tutor 界面隐藏了会话侧边栏，历史入口放在**会话头部**：「新对话」和「清空历史」两个按钮。

按钮只在**已有对话内容的会话**里出现：DSH 在空白新会话（Hero 态）会隐藏整条标题栏 chrome，此时看不到属正常。部署后仍不显示，按 [部署文档 §9](./部署-Ubuntu服务器.md) 排查。

- **清空历史**是两步确认：点「清空历史」→ 出现「清空全部历史？不可恢复」→ 点「确认清空」（6 秒不点自动取消）。
- 效果：当前工作区的**全部会话**被删除——不是压缩、不是归档隐藏，磁盘上的会话日志文件会被物理删除，然后自动开一个新会话。
- **当前正在进行的会话**：它的日志文件被运行中的进程占用，无法当场删除；插件把它记入待删清单（`~/.dsh/storages/ai-tutor-purge-pending.json`），在该会话释放时或**下次服务启动时**兜底删除。所以刚点完清空时当前会话还在（界面正常），重启服务后彻底消失。
- 清理范围只限当前工作区（按工作区会话列表 + cwd 过滤），**不会**碰同一 DSH 上其他工作区/其他 profile 的会话。
- 关闭物理删除（只归档不删文件）：`purgeArchivedFiles: false`。非默认存储布局才需要显式设置 `sessionsRoot`。

> 实现说明：DSH 没有"硬删除会话"的 API，只有软归档。guard 的 client 半边把当前工作区会话逐个 `archiveSession(stopActivity:true)`，host 半边监听 `workspace/session-stop` 事件删除对应目录（含投影缓存），配合待删清单实现"清理而非压缩"。

### 规划中：应用内表单

DSH 的设置表单需要插件自带 client UI（volatile Config 只是数据层，不会自动生成表单），guard 的应用内表单（设置 → 通用 → 「AI 辅导内容监护」）在路线图上，尚未实现。

另注意 DSH 的机制：**非 loopback 访问时表单改动只存内存、不写回 patch 层**（`dsh-client-ui-settings` 的 `persistence = isLoopback ? "host" : "memory"`）。局域网访问的服务器要持久化配置，走 SSH 隧道后在浏览器改，或直接编辑 patch 文件：

```bash
ssh -L 3090:127.0.0.1:3090 <服务器用户>@<服务器IP>
# 浏览器打开终端打印的 token URL（127.0.0.1:3090）
```

## 生效验证

1. 发「**黑洞是如何形成的**」→ 应走**直接讲解**：第一句就给结论，不反问"你知道黑洞吗"、不要求孩子先猜。
2. 发「**这道数学题不会做**」（或拍一道题）→ 应走**引导式**：先问你是怎么想的、卡在哪一步，不直接报答案。
3. 对孩子界面发一句「**陪我玩游戏**」→ 模型应温和拒绝并引导回作业。
4. 家长把 `guidedTopics` 加上「英语单词背诵」后，发「帮我背英语单词」→ 正常执行。
5. 深浅调节：发「光合作用是什么」，看结尾是否顺带问年级；下一轮说"我上四年级"，用词应更简单。

## 改了配置不生效？按顺序排查

1. **确认改的是服务真正读取的那份文件**。systemd 服务以哪个用户运行，就读哪个用户的 `~/.dsh`：
   ```bash
   systemctl cat ai-tutor | grep -i '^User='
   ```
   若服务以 `root` 或专用用户运行，而你编辑的是自己登录账号下的 `~/.dsh/profiles/ai-tutor/cordis.patch.yml`，服务不会看到改动——这是最常见的坑。
2. **确认 guard 已安装**（v1.1 才有监护）：
   ```bash
   dsh plugin --profile ai-tutor list | grep guard
   ```
   没有输出说明服务器还是 v1.0，先按部署文档 §7 升级（git pull + guard 目录 `npm install` + `dsh plugin add`）。
3. **确认覆盖语法**：行首 `- id: ai-tutor-guard`、无 `insert`、`config` 写完整对象（见上文示例）。缩进必须是 2 空格层级，YAML 缩进错误会被静默跳过。
4. **重启服务**消除热重载的不确定性：`sudo systemctl restart ai-tutor`。
5. **新开一个对话**再测（旧对话的上下文里可能还留着旧的拒绝行为）。
6. **区分两种改动的生效方式**：白名单（`guidedTopics` / `directTopics` / `blockedKeywords` / `extraPolicy`）是 volatile 配置，保存即热生效；**回复模式的讲法**在 preset 人格里（bundle 侧），要 `git pull` + `dsh plugin add` + 重启服务才生效，见 [部署文档 §7](./部署-Ubuntu服务器.md)。
7. **看模型实际读到的指令**：`node scripts/guard-policy.mjs my-guard.json` 打印注入的白名单与路由规则。里面没有你刚加的条目 → 配置没到位（回到第 1、3 步）；有条目但行为不对 → 是提示词遵循问题，换云端模型或收紧条目表述。

> 快速判别法：发一句白名单外的话题（如「陪我打游戏」）。若模型说「这个不在我们约定的辅导范围里」，说明监护**已生效**，只是白名单还是旧内容（配置没到位）；若模型用完全不同的措辞拒绝（如「这个话题可以和爸爸妈妈聊聊」），说明监护没装或没挂载，只有 persona 边界在起作用。

> 知识类问题仍被反问引导？先确认服务已升级到 v1.3 并重启过（persona 在 bundle 侧），再用第 7 步确认注入文本里有「模式 A」的路由规则，最后**新开一个对话**测——旧对话里模型会延续之前的讲法。

## 已知边界

- 关键词兜底只匹配**文本**；拍照图片里的文字不做关键词匹配（提示词白名单仍生效）。
- 白名单靠模型遵守，不是绝对隔离；需要硬隔离（工具级/会话级）属于后续 M1 范围。
- **话题路由同样靠模型遵守提示词**：同一句话在不同模型上表现可能有差异，本地小模型（如 27B）的路由稳定性弱于云端模型。要确定性分类（用小模型逐条判定命中哪份白名单）在 M1 路线图上。
- 监护对 profile 内所有会话统一生效，暂不区分家长/孩子身份（v1 单 profile 假设）。
