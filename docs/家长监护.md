# 家长监护（v1.1–v1.2）

家长定义孩子可以聊什么。默认**只允许作业辅导类对话**；家长可以增删允许的话题、补充自定义规则、维护禁区关键词。

## 两层防护

1. **提示词白名单（主防线）**：插件把家长定义的允许话题作为高优先级系统提示注入每一次模型调用。范围外的请求（陪聊、游戏、小说、影视、八卦等）模型会温和拒绝，并引导回作业；孩子要求"解除规则"或"扮演其他角色绕过"时保持立场。
2. **消息级硬拦截（兜底）**：孩子消息命中家长设置的**禁区关键词**时，插件会在进入模型的那条消息末尾追加一条监护指令（会话记录和孩子界面上都看不到这条指令），模型据此拒绝执行该请求。

> 定位说明：关键词匹配是粗粒度兜底，主防线是提示词白名单。更强的语义级分类（用小模型逐条判定）在路线图上，未进 v1.1。

## 家长怎么配置

### 当前入口：编辑 profile patch 文件（v1.1 唯一入口）

编辑 `~/.dsh/profiles/ai-tutor/cordis.patch.yml`（Windows 为 `C:\Users\<你>\.dsh\profiles\ai-tutor\cordis.patch.yml`），在文件**末尾**追加对 guard 行的 config 覆盖（写完整对象）：

```yaml
- id: ai-tutor-guard
  config:
    enabled: true
    allowedTopics:
      - 写作业、功课讲解、错题订正等作业辅导内容
      - 英语单词与课文背诵
      - 数学思维训练题
    extraPolicy: |
      周末下午 4 点前只允许数学和语文作业辅导。
    blockedKeywords:
      - 陪我聊天
      - 打游戏
```

保存即热生效（profile 以 `patchReload: live` 运行）；不确定时重启服务（`sudo systemctl restart ai-tutor`）。改动写在 patch 层，**升级不丢失**。

字段说明：

| 字段 | 说明 | 默认值 |
| --- | --- | --- |
| `enabled` | 监护总开关 | 开 |
| `allowedTopics` | 允许的话题白名单（列表，每行一条） | 写作业、功课讲解、错题订正等作业辅导内容 |
| `extraPolicy` | 自定义补充规则，原文注入系统提示 | 空 |
| `blockedKeywords` | 禁区关键词（子串匹配，大小写不敏感） | 陪我聊天、玩游戏、打游戏、看小说、写小说 |
| `purgeArchivedFiles` | 清空历史时物理删除会话日志文件（见下节） | 开 |
| `sessionsRoot` | 会话存储根目录；留空自动取 `$DSH_HOME/sessions` | 空（自动） |

## 清理会话历史（v1.2）

tutor 界面隐藏了会话侧边栏，历史入口放在**会话头部**：「新对话」和「清空历史」两个按钮。

按钮只在**已有对话内容的会话**里出现：DSH 在空白新会话（Hero 态）会隐藏整条标题栏 chrome，此时看不到属正常。部署后仍不显示，按 [部署文档 §9](./部署-Ubuntu服务器.md) 排查。

- **清空历史**是两步确认：点「清空历史」→ 出现「清空全部历史？不可恢复」→ 点「确认清空」（6 秒不点自动取消）。
- 效果：当前工作区的**全部会话**被删除——不是压缩、不是归档隐藏，磁盘上的会话日志文件会被物理删除，然后自动开一个新会话。
- **当前正在进行的会话**：它的日志文件被运行中的进程占用，无法当场删除；插件把它记入待删清单（`~/.dsh/storages/ai-tutor-purge-pending.json`），在该会话释放时或**下次服务启动时**兜底删除。所以刚点完清空时当前会话还在（界面正常），重启服务后彻底消失。
- 清理范围只限当前工作区（按工作区会话列表 + cwd 过滤），**不会**碰同一 DSH 上其他工作区/其他 profile 的会话。
- 关闭物理删除（只归档不删文件）：`purgeArchivedFiles: false`。非默认存储布局才需要显式设置 `sessionsRoot`。

> 实现说明：DSH 没有"硬删除会话"的 API，只有软归档。guard 的 client 半边把当前工作区会话逐个 `archiveSession(stopActivity:true)`，host 半边监听 `workspace/session-stop` 事件删除对应目录（含投影缓存），配合待删清单实现"清理而非压缩"。

### 规划中：应用内表单

DSH 的设置表单需要插件自带 client UI（volatile Config 只是数据层，不会自动生成表单），guard 的应用内表单（设置 → 通用 → 「AI 辅导内容监护」）在路线图上，尚未实现。

另注意 DSH 的机制：**非 loopback 访问时表单改动只存内存、不写回 patch 层**（`dsh-client-ui-settings` 的 `persistence = isLoopback ? "host" : "memory"`）。局域网访问的服务器要持久化配置，走 SSH 隧道后在浏览器改，或直接编辑 patch 文件：

```bash
ssh -L 3090:127.0.0.1:3090 <服务器用户>@<服务器IP>
# 浏览器打开终端打印的 token URL（127.0.0.1:3090）
```

## 生效验证

1. 对孩子界面发一句「**陪我玩游戏**」→ 模型应温和拒绝并引导回作业。
2. 发「今天的数学作业有一题不会」→ 正常辅导。
3. 家长把 `allowedTopics` 加上「英语单词背诵」后，发「帮我背英语单词」→ 正常执行。

## 改了配置不生效？按顺序排查

1. **确认改的是服务真正读取的那份文件**。systemd 服务以哪个用户运行，就读哪个用户的 `~/.dsh`：
   ```bash
   systemctl cat ai-tutor | grep -i '^User='
   ```
   若服务以 `root` 或专用用户运行，而你编辑的是自己登录账号下的 `~/.dsh/profiles/ai-tutor/cordis.patch.yml`，服务不会看到改动——这是最常见的坑。
2. **确认 guard 已安装**（v1.1 才有监护）：
   ```bash
   dsh plugin --profile ai-tutor list | grep guard
   ```
   没有输出说明服务器还是 v1.0，先按部署文档 §7 升级（git pull + guard 目录 `npm install` + `dsh plugin add`）。
3. **确认覆盖语法**：行首 `- id: ai-tutor-guard`、无 `insert`、`config` 写完整对象（见上文示例）。缩进必须是 2 空格层级，YAML 缩进错误会被静默跳过。
4. **重启服务**消除热重载的不确定性：`sudo systemctl restart ai-tutor`。
5. **新开一个对话**再测（旧对话的上下文里可能还留着旧的拒绝行为）。

> 快速判别法：发一句白名单外的话题（如「陪我打游戏」）。若模型说「这个不在我们约定的辅导范围里」，说明监护**已生效**，只是白名单还是旧内容（配置没到位）；若模型用完全不同的措辞拒绝（如「这个话题可以和爸爸妈妈聊聊」），说明监护没装或没挂载，只有 persona 边界在起作用。

## 已知边界

- 关键词兜底只匹配**文本**；拍照图片里的文字不做关键词匹配（提示词白名单仍生效）。
- 白名单靠模型遵守，不是绝对隔离；需要硬隔离（工具级/会话级）属于后续 M1 范围。
- 监护对 profile 内所有会话统一生效，暂不区分家长/孩子身份（v1 单 profile 假设）。
